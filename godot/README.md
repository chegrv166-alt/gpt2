# Ashen Covenant — «Имя, которого нет»

Первый самостоятельный Godot-эпизод новой партийной RPG. Версия `0.7.1` с живописной графикой; предыдущий релиз первого эпизода — `0.7.0`; версия 0.6 на Phaser остаётся отдельным приложением в корне репозитория.

## Запустить

Godot **4.6.3** (стандартный, без .NET): импортировать `project.godot`, затем F6/F5, либо:

```sh
cd /workspace/gpt2
godot --path godot
```

В самостоятельной Windows-сборке открыть `Ashen-Covenant-Chronicle.exe`. Установка Godot игроку не требуется. Linux: `./Ashen-Covenant-Chronicle.x86_64`. Собранные локальные файлы находятся в `godot/build/` и не коммитятся.

## Что играть

Вы — хронист, в протоколе казни которого значится человек, не существующий в реальности. Исследуйте Вель, соберите независимые свидетельства, доберитесь до архива и выберите судьбу закрытой лечебницы.

Три героя: проклятый Хронист, непроклятая стрелок Мирра и проклятый лекарь Сава. Доступ к архиву можно оплатить, обосновать документами, получить через цистерну или захватить механизм врат. Доступ и финальное решение независимы.

Три исхода: вывести узников, сорвать ритуал или обменять подлинник на имена покровителей. Задания заканчиваются по своей цели, а не обязательным уничтожением всех врагов. Доверие, свидетельства, последствия и чужое присутствие сохраняются в хронике. После завершения можно продолжать исследование или начать другой путь.

## Управление

- ЛКМ по земле — идти; ЛКМ по зданию/его подписи — подойти и поговорить/исследовать.
- Колесо — масштаб; средняя кнопка мыши или WASD/стрелки — камера.
- J — хроника и возможность отступить из боя.
- F5 / F9 — ручное сохранение / загрузка (включая активный бой).
- Esc — закрыть обычную панель. При перехвате голоса используйте кнопку возврата контроля.
- В бою: 1 — шаг, 2 — удар, 3 — заимствованный/личный приём, 4 — обращение, 5 — прикрыться, E — выбрать механизм, Пробел — завершить активацию. После выбора действия нажмите на цель.
- Tab / кнопка «Голос» — выбрать личность, чей приём использует Хронист.

## Бой и обращение

По 2 очка действия. После активации героя действует противник, затем следующий герой. Очередь, намерения и цель видны справа/снизу. Перемещение ограничено проходимой сеткой, выстрелы и лечение — видимостью.

Обращение повышается на один уровень за 1 ОД, максимум 2. Растут личная дальность/урон и восстановление; совместимость падает с 100% до 65% и 30%. Лечение/связки учитывают состояние обоих участников. Возврат к человеческому телу происходит после боя; чужие голоса остаются.

- Дознаватель: «Выявить» — открывает уязвимость для следующего удара.
- Палач: «Приговор» — тяжёлый удар, преодолевающий защиту.
- Судья: «Обязать» — лишает противника одного действия.
- Бандит: «Грязный удар» — ранение с кровотечением.
- Мирра: выстрел и совместный удар ближайшего союзника; Сава: перевязка союзника или самостоятельное восстановление.

Чужие приёмы увеличивают давление соответствующего голоса. От 50 знакомый собеседник/место может вызвать настоящий перехват разговора: реплика произносится сама, реакция и последствия применяются один раз. Отдых у костра требует припас и помогает успокоить голоса.

Отступление/поражение возвращают подготовку перед столкновением; можно повторить или выбрать другой путь. Ручной файл хранится в Godot `user://chronicle_save.json`; неудачная загрузка не заменяет текущую игру.

## Проверить и собрать

```sh
bash godot/tools/check.sh
bash godot/tools/export.sh
```

Экспорт требует официальные шаблоны Godot 4.6.3 в стандартном каталоге `export_templates/4.6.3.stable`. Используются Windows x86_64 и Linux x86_64 release templates. Платные сервисы и токены не нужны.

В облачной среде проверка Godot требует разрешённого режима выполнения. Для изоляции настроек можно задать XDG_DATA_HOME, XDG_CONFIG_HOME и XDG_CACHE_HOME на доступные локальные папки. Модельные проверки работают с `--headless`. Для настоящих скриншотов нужен дисплей (например, Xvfb и Mesa); `--headless` сам по себе не подтверждает отрисовку.

Визуальная проверка: `godot --path godot --audio-driver Dummy -- --capture=/tmp/chronicle.png`; с `--battle-preview` — кадр ритуального боя. Это локальные диагностические параметры.

## Границы прототипа

Цель эпизода — проверить исследование, диалоги, последствия, короткие активации и цену обращения. 20–30 минут — целевая длительность, требующая живого плейтеста. Большой регион, найм дополнительных спутников, полная прокачка/инвентарь, озвучка и окончательная художественная проработка — последующая работа. Имена и часть окружения предварительные. Согласованная загадка прошлого не раскрывается окончательно.

Ассеты и лицензии: `assets/PROVENANCE.md`. Историческое насилие передаётся текстом без изображения нападений.

## Публикация и проверка запуска

Workflow `.github/workflows/godot-release.yml` отдельно собирает Godot-игру на Windows и Linux. Официальные Godot 4.6.3 и release templates проверяются по SHA512. На каждой ОС выполняются модели, интеграция интерфейса и прохождение; затем запускается именно экспортированный исполняемый файл с проверкой загрузки мира, отряда и HUD. Проверка запуска использует headless-режим; графическому запуску нужен OpenGL 3.3.

Тег `v0.7.*` публикует Windows ZIP, Linux tar.gz с исполняемым файлом и SHA256SUMS только после успеха обеих платформ. Godot и Node.js игроку не требуются. Старый Electron workflow обслуживает только теги 0.2–0.6.

## Живописная графика — версия 0.7.1

Оригинальные здания, девять мест, деревья, герои, противники, узница, четыре анатомические формы обращения и двенадцать портретов заменяют временное оформление. Грунт, мокрая мостовая, вода, туман, пепел и локальный свет собраны в Godot. HUD и диалоги используют общую палитру железа, кости и выцветшего багряного. Прозрачные края крупных силуэтов не перехватывают клики; области рисунка и взаимодействия согласованы. Окно масштабирует компоновку, а не уменьшает весь интерфейс; при 960×640 очередь и намерения врагов видны без прокрутки.

[Реальный игровой кадр](../docs/art-direction/gameplay/exploration.png), [формы обращения](../docs/art-direction/gameplay/mutation.png), [диалог](../docs/art-direction/gameplay/dialogue.png), [бой 960×640](../docs/art-direction/gameplay/battle-960.png). Это кадры работающей сцены, снятые через Xvfb/Mesa, а не художественный концепт. Кадр обращения использует отдельную тестовую расстановку состояний для показа обеих форм, без утверждения, что это запись прохождения.

Источники иллюстраций и точные запросы: `assets/painted/`. Их PNG сохранены без редактирования, границы и масштаб задаются ресурсами Godot. Анимация ограничена процедурным движением и дыханием; отдельного набора покадровых направленных анимаций пока нет.

Для повторения снимков нужен графический дисплей:

```sh
godot --path godot --audio-driver Dummy --script tests/capture_art.gd -- --scenario=exploration --output=/tmp/chronicle.png
godot --path godot --resolution 960x640 --audio-driver Dummy --script tests/capture_art.gd -- --scenario=battle --output=/tmp/battle-small.png
```

Доступны также сценарии `mutation` и `dialogue`. Тестовый захват не включается в экспорт. Запуск экспортированной Linux-сборки с `-- --capture=/tmp/native.png` проверяет настоящий встроенный пакет. [Скачать релиз 0.7.1](https://github.com/chegrv166-alt/gpt2/releases/tag/v0.7.1): Windows ZIP и Linux tar.gz. Публикация проходит только после проверок обеих платформ в GitHub Actions; запуск экспортированного приложения проверяется в headless-режиме, отрисовка дополнительно проверена на Linux.
